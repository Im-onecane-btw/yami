# Заметки о безопасности

[English](SECURITY.md) · Русский

Чему yami доверяет, что открывает наружу и что проверено (аудиты 2026-11-03 и 2026-11-04).

## Поверхности

| Поверхность | Кто может до неё дотянуться | Защита |
|---|---|---|
| `$XDG_RUNTIME_DIR/yami-shell.sock` (IPC) | процессы того же пользователя | права сокета 0600, UID собеседника проверяется (`SO_PEERCRED`), читается одна строка ≤ 4 КБ с таймаутом 2 с; команды только открывают панели, блокируют, делают скриншоты или выходят: ни одна не запускает программу |
| агент polkit (`/org/yami/PolkitAgent`, системная шина) | polkitd | вызовы от кого-либо, кроме владельца `org.freedesktop.PolicyKit1`, отклоняются, так что никакой другой процесс не может вызвать окно пароля; пароль уходит только в `polkit-agent-helper-1` и стирается из памяти после использования |
| экран блокировки | место за компьютером | `ext-session-lock`: если шелл умрёт, niri держит экран заблокированным. Пароль проверяет PAM (только `pam_unix`, свой файл службы в `~/.local/state/yami/pam`, так что faillock не блокирует учётную запись из-за опечаток; пользователь не из `/etc/passwd` — LDAP, SSSD, systemd-homed — идёт через системную службу `system-local-login` или `login`), копии стираются после проверки; монитор, подключённый во время блокировки, получает свою поверхность блокировки |
| шторка приватности (Mod+Shift+H) | трансляции экрана через xdg-desktop-portal (OBS PipeWire, Discord, браузеры) | на yami-niri ≥ `.4` слой, который рисуется только в трансляции (`show-only-in`), закрывает экран застывшим кадром — размытым (или пикселями по 24 px, или обоями); панели шелла, открытые тем временем, получают новую шторку поверх; с `.5` закрыто и отдельно показанное окно (своей частью шторки). Переключатель Alt+Tab в niri рисуется поверх всех слоёв и не закрывается; захват через wlr-screencopy (grim, OBS wlrobs) не закрывается. На другом niri вместо этого закрываются окна |
| бэкенды порталов (FileChooser, ScreenCast, FileManager1) | xdg-desktop-portal, программы того же пользователя на сессионной шине | программы в песочнице доходят до них только через фронтенд портала; выбор экрана — собственное окно шелла |
| уведомления, трей | программы того же пользователя | рисуются как текст и декодированные картинки (декодеры на чистом Rust); сырые картинки проверяются по размеру до выделения памяти (≤ 1024², без переполнения целых), файлы, названные программой (`image-path`, обложка `file://`), читаются только обычные и ≤ 16 МБ, декодеры работают с ограничением 64 МБ; не больше 64 значков трея; ничего не выполняется, кроме действия, на которое нажал пользователь; каждую службу можно выключить (настройки → службы) |
| обложки альбомов | плеер (MPRIS `artUrl`) | `curl -q` (без пользовательского curlrc), только http(s), после переадресаций только https, ≤ 3 переадресаций, ≤ 16 МБ, 8 с; выключенный `mediaArtNet` держит шелл без сети |
| файловый менеджер | съёмные носители | `.trashinfo` на съёмном диске не может указывать за пределы этого диска (`..` отклоняется); архивы идут через `bsdtar`, который отклоняет абсолютные пути и `..`; FileManager1 открывает не больше 16 папок за вызов |
| просмотрщик картинок | файлы, которые ты открываешь | анимации ограничены 600 кадрами и 1 ГБ декодированных кадров |
| выбор обоев | картинки папки обоев | только обычные нескрытые файлы png/jpg/webp, не больше 500 из папки; декод в фоновой нити шелла с теми же пределами, что у yami-files (больше 40 Мпикс не декодируется, потолок 256 МБ), миниатюры в кеше `~/.cache/yami/thumbs`; в памяти — только видимые строки, при закрытии всё отпускается |
| открытие файлов | щелчки пользователя | строки `Exec=` разбираются в argv без оболочки, имена файлов никогда не подставляются в командную строку |
| свои сочетания клавиш | пользователь (настройки → клавиши) | запускаются niri через `sh -c`, как любой `spawn-sh` в niri |
| скрипты бара (`~/.config/yami/modules`) | собственные исполняемые файлы пользователя | работают, только пока их модуль в баре, каждый в своей группе процессов во главе с маленьким `sh`: вся группа (скрипт и то, что он запустил) получает SIGTERM, когда модуль убирают из бара или шелл умирает (`PR_SET_PDEATHSIG` у лидера); вывод читается построчно (строка длиннее 4 КБ пропускается); `click` модуля запускается через `sh -c`, как своя клавиша |
| лаунчер `>` и `/` | то, что набирает пользователь | `>` запускает набранную команду в терминале (как если набрать её там); `/` только обходит домашнюю папку (без скрытых папок, без папок-ссылок, ≤ 8 уровней, ≤ 60 000 записей) и открывает выбранное через `xdg-open` |
| ответ из уведомления | программа, приславшая уведомление | текст уходит только как `NotificationReplied` этому уведомлению; поле стирается после отправки, ничего не хранится и не копируется |
| `yami theme import` | файл от кого угодно | только ключи вида (палитра, эффекты, шрифты, бар, виджеты, вид дока, отступы, курсор) и картинка обоев (сохраняется обычным файлом в `~/.local/share/yami/wallpapers`, имя очищено от пути); никогда — сочетания клавиш, команды, скрипты или источник обновлений. Перед любым импортом всё, что он может заменить, копируется в `~/.local/state/yami/before-import-*.json` (тот же формат, хранятся последние пять; `yami import FILE --yes` возвращает) |
| `yami import` | твоя собственная резервная копия | то же, плюс все остальные настройки; свои сочетания клавиш, `niri/user.kdl` и скрипты бара перечисляются и пишутся только с `--yes`; пути должны быть простыми и относительными внутри `~/.config` (`..` и абсолютные пути отклоняются); `updateRepo` и `updateVerify` никогда не импортируются |
| `yami report` | ты, для issue | ничего не отправляется; строки с именами пароля, токена, секрета или ключа очищаются, путь к дому, имя пользователя и хоста заменяются; архив стоит прочитать, прежде чем прикладывать |
| процессы шелла | настройки пользователя | wlsunset (ночной свет) запускается с фиксированными аргументами; у него и у помощников музыки, звука и визуализатора (playerctl, pactl, parec) стоит `PR_SET_PDEATHSIG`, так что ни один не переживёт шелл или его перезапуск |

## Установщик

- Работает от пользователя; `sudo`/`doas` — только для пакетов, служб, темы SDDM, профиля NVIDIA
  и, если у пользователя нет лимита realtime, `setcap cap_sys_nice=ep` на бинарник yami-niri
  (композитор сбрасывает все capabilities сразу после того, как взял свой класс планирования;
  любая запись в файл стирает capability).
- Загрузки: сам репозиторий (git по HTTPS), rustup, когда Rust дистрибутива слишком старый
  (только `https`, TLS 1.2+), Monocraft закреплённой версии со сверкой SHA-256. niri и smithay
  скачиваются на закреплённых коммитах, патчи берутся из этого репозитория.
- `bash <(curl …)` запускает код из сети: прочитай сначала `install.sh`, если не доверяешь
  источнику; `--dry-run` показывает план.

## Обновления

- Обновлятор работает в своём клоне (`~/.local/share/yami/src`), запускает git без вопросов
  (`GIT_TERMINAL_PROMPT=0`, хуки выключены) и с таймаутом на зависание; теги скачиваются без
  `--force`, так что тег, переписанный на сервере, не заменяет уже виденный.
- Подписи: доверенные ключи берутся из `keys/allowed_signers` уже установленной версии (доверие
  при первой установке, как и сама установка). Как только в этом файле есть ключи, выпуск с
  неподписанным тегом или подписанный другим ключом отклоняется (`updateVerify` `auto`), так что
  тот, кто получил доступ на запись в репозиторий, всё равно не сможет выпустить обновление.
  Подпись засчитывается только с совпавшим principal (`gpg.minTrustLevel=fully`, и «No principal
  matched» отклоняется, даже где старый git завершился бы с 0). Выпуски делаются
  `tools/release.sh`, который отказывается делать неподписанный тег, когда ключи есть.
- Установка: `install.sh --update` из нового дерева от пользователя, без sudo; прежние бинарники
  сохраняются для `yami update rollback`. Игра в фокусе откладывает перезапуск шелла.
- Закрытый или открытый репозиторий: тот же HTTPS-адрес. Пока он закрыт, git использует
  помощник учётных данных пользователя (`gh auth login`); открытие репозитория не требует
  изменений у клиентов.

## Известные компромиссы

- `theme.conf.user` и `background.png` темы SDDM принадлежат устанавливавшему пользователю, чтобы
  палитра и обои следовали за шеллом; на машине, общей с недоверенными пользователями, сделай их
  владельцем root (тогда `tools/sddm-install.sh` нужно запускать после смены палитры).
- Файл службы PAM экрана блокировки лежит в каталоге состояния пользователя: процесс от имени
  пользователя мог бы его ослабить, но такой процесс и так управляет сессией.
- История буфера обмена (cliphist) пропускает записи, которые менеджеры паролей помечают как
  секретные (`x-kde-passwordManagerHint`, `CLIPBOARD_STATE=sensitive` у wl-clipboard); всё
  остальное скопированное хранится до удаления (`Mod+V`, `Del`).

## Счётчик установок

У yami нет телеметрии: шелл никогда ничего не сообщает, а обновления — это `git fetch` открытого
репозитория. Значок «installs» в README считает одно: установщик **один раз на машину** скачивает
крошечный файл `yami-installs.txt` из последнего выпуска на GitHub и выбрасывает его. GitHub
считает скачивания файлов выпусков; `.github/workflows/stats.yml` раз в день складывает эти
числа и пишет значок в ветку `stats`.

- Запрос ничего не несёт о тебе или машине: ни идентификатора, ни версии, ни настроек. GitHub
  видит то же, что при любой загрузке (твой IP-адрес), как и при `git clone`, который установщик
  и так делает.
- Один раз — значит один раз: метка `~/.local/state/yami/counted` делает последующие обновления
  тихими. Машины, установленные до счётчика, учитываются один раз, при следующем обновлении.
- Отказаться: `install.sh --no-count` или `YAMI_NO_COUNT=1` в окружении (в CI и при `--dry-run`
  тоже пропускается). Создать файл-метку вручную — то же самое.
- Он считает установки, а не людей и не активные машины: переустановка после удаления
  `~/.local/state/yami` считается снова, удаление не вычитается.
